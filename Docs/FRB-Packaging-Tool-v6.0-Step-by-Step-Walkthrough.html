How v6.0 Feels

v6.0 is built to feel guided rather than mechanical. You choose the media, confirm the metadata, review the package helper output, and let the tool carry the workflow through validation and reporting. The live process tab gives you a running commentary so you always know what stage you are in.

Success signal: when the package is complete, the final validation report lands in the package docs folder with the correct naming convention, opens automatically, and the tool resets back to Main Settings for the next package.

Step-by-Step Walkthrough

Step 1 - Open FRB-Packaging-Tool v6.0

Start the tool from the approved packaging location. The Main Settings tab should appear first. This is your control room for the entire run.

Step 2 - Enter or Confirm the Package Metadata

Enter vendor, product name, edition if needed, and version. These values drive the package folder, the validation report file name, and the overall identity of the package.

Step 3 - Choose the Installation Media

Select the EXE or MSI file. v6.0 reads the installer metadata, detects installer type, and starts auto-populating what it can so you do not have to repeat work.

Step 4 - Review the Install Context Prompt

If the installer suggests user or system context, choose the one that matches the deployment intent. This keeps the package aligned with how it will be delivered in production.

Step 5 - Review Package Helper Output

Open Package Helper to see curated suggestions for install switches, uninstall values, and reusable command snippets. The goal is to reduce manual typing and make the packaging decision faster.

Step 6 - Review Custom Commands

The custom command sections let you inspect or edit the package-specific Startup.pss logic. Existing packages can rehydrate these sections so you can pick up work where it was last left off.

Step 7 - Create or Update the Package

Start the packaging workflow. The tool copies the template, updates the project files, inserts custom command content, and prepares the package folder structure for the next stage.

Step 8 - Build and Run Validation

Build the package and continue into validation. This is where v6.0 shines: the workflow now captures install progress, Programs and Features evidence, Start Menu evidence, and the application-open screenshot that proves the app launches.

Step 9 - Review the Validation Report

The report is copied into the package docs folder using the correct naming convention and opens automatically. This is the version you want to show and keep.

Step 10 - Complete Uninstall Validation if Required

If the workflow includes uninstall validation, complete the technician prompts and confirm the results before finishing the run.

Step 11 - Finish and Reset

Once everything is done, the tool clears the live process log and returns to Main Settings so the next package starts with a clean slate.

What to Watch For
  • Correct package path and naming.
  • Validation report opens from the docs folder, not a temp location.
  • Live process tab messages keep pace with the workflow.
  • Application-open screenshot is captured as proof of launch.
What a Good Run Looks Like
  • Tool returns to Main Settings when complete.
  • Report is easy to read and clearly tied to the package.
  • No extra popups or duplicate report openings.
  • You can immediately begin the next package.

Completion Checklist

  • Package folder created or updated
  • Startup.pss customized correctly
  • Install switches reviewed
  • Uninstall values reviewed
  • Validation screenshots captured
  • Report copied to docs folder
  • Report opened for review
  • Live process log cleared
  • Main Settings tab restored
  • Ready for the next package

Final Message

FRB-Packaging-Tool v6.0 is designed to feel complete. It does the work, explains the work, and leaves behind a polished report that shows the value of the effort. That is the version you hand to someone else with confidence.
